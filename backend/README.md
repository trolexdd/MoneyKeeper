# MoneyKeeper Backend

FastAPI backend foundation. Business modules are added incrementally.

## Requirements
- Python 3.12+
- PostgreSQL 16 (or compatible)

## Local setup

Create the repository-root `.env` from `.env.example`, then set a unique local `APP_SECRET_KEY` and the PostgreSQL connection string.

Start PostgreSQL from the repository root:

```bash
docker compose up -d db
```

Then open a terminal in `backend/`:

```bash
python -m venv .venv
# Windows CMD:
.venv\Scripts\activate.bat
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux:
# source .venv/bin/activate

python -m pip install -e ".[dev]"
alembic upgrade head
uvicorn app.main:app --reload
```

API:
- `http://127.0.0.1:8000/health/live` — process liveness
- `http://127.0.0.1:8000/health/ready` — PostgreSQL readiness
- `http://127.0.0.1:8000/docs` — interactive OpenAPI docs

## Database migrations

Alembic configuration lives in `alembic.ini`; migration scripts are in `migrations/versions/`. The database URL is loaded from application settings, so the same `DATABASE_URL` is used by the API and migrations.

Apply migrations:

```bash
alembic upgrade head
```

Show the current revision:

```bash
alembic current
```

Create a new migration after changing SQLAlchemy models:

```bash
alembic revision --autogenerate -m "describe the schema change"
```

Always review autogenerated migrations before applying them.

## Tests

From `backend/`:

```bash
pytest
```

The tests for liveness and SQLAlchemy model metadata do not require a running PostgreSQL server. The readiness endpoint is expected to return HTTP 503 while PostgreSQL is unavailable.

## Configuration

The backend reads environment variables, including `DATABASE_URL`, `APP_ENV` and `APP_SECRET_KEY`. For local development, copy the repository-root `.env.example` to the repository-root `.env` and keep it out of Git. The backend is started from `backend/`, so its settings load `../.env`. The default secret is development-only and must be replaced before any deployment.
