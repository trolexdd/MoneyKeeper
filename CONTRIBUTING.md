# Contributing

## Рабочий процесс
1. Не коммитить напрямую в `main`.
2. Создавать короткоживущую ветку от актуального `main`: `feat/<name>`, `fix/<name>`, `docs/<name>`.
3. Делать небольшие логически цельные коммиты.
4. Открывать Pull Request с описанием задачи, решений и проверок.
5. Не объединять PR, если проверки не проходят.

## Качество
- Добавлять тесты для новой логики и исправлений.
- Проверять негативные сценарии и права доступа.
- Не использовать float для денежных значений.
- Обновлять документацию и миграции вместе с кодом.
- Не оставлять реальные секреты или финансовые данные в fixtures.

## Совместная работа
Перед крупным изменением согласовать границы задачи и публичные интерфейсы. Не переписывать чужие незавершённые изменения без обсуждения.
