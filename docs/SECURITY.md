# Security baseline

## Секреты и данные

- Не коммитить .env, bot tokens, AI API keys, пароли, дампы БД и реальные финансовые данные.
- В репозитории хранить только безопасный .env.example.
- Не создавать production-аккаунты с известными тестовыми паролями.
- Не использовать тестовые креды в production.
- Не логировать токены, пароли, session cookies и лишнее содержимое финансовых запросов.
- Для подписи JWT задавать уникальный случайный APP_SECRET_KEY длиной не менее 32 символов.

## Authentication

- Пароли хешируются Argon2id через pwdlib; открытый пароль не сохраняется.
- Для новых паролей используется Argon2id: 19 MiB памяти, 2 прохода и 1 lane; существующие хеши с прежними параметрами автоматически обновляются после успешной проверки пароля.
- Access token — короткоживущий JWT HS256 (по умолчанию 15 минут).
- Refresh token — случайный opaque token; в БД хранится только SHA-256 hash.
- Refresh token ротируется при каждом обновлении; повторное использование старого токена отклоняется.
- Сессии хранят срок действия и время отзыва; защищённые endpoints проверяют состояние сессии в БД.
- Минимальная длина пароля при регистрации — 12 символов; максимум — 128.
- Для несуществующего email выполняется dummy Argon2 verify, чтобы уменьшить разницу во времени ответа.
- Rate limiting на login/reset ещё требуется добавить до публичного развёртывания.
- Не передавать пароли через обычные Telegram-команды.
- Для Telegram Mini App проверять подпись initData на backend, timestamp и допустимый возраст данных.

## Authorization

- Проверять доступ к каждому account/transaction/workspace на backend.
- Роли viewer/editor/owner должны применяться в сервисном слое.
- Административные действия журналировать.
- Не полагаться на скрытие элементов UI как на контроль доступа.

## Financial integrity

- Использовать Decimal/NUMERIC, не float.
- Переводы проводить атомарно.
- Изменяющие запросы защищать idempotency key.
- Запрещать смешивание валют без явной конвертации.
- Для undo сохранять связь с исходной операцией и проверять актуальное состояние.

## Operations

- Production только через HTTPS.
- PostgreSQL не публиковать напрямую в интернет.
- Регулярно проверять backup и восстановление.
- Обновлять зависимости и запускать security checks.
- AI-провайдерам отправлять минимально необходимый контекст; не передавать секреты.
