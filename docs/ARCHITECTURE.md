# Архитектура

## Архитектурный стиль
Модульный монолит backend. API, Telegram Bot и worker — отдельные процессы, использующие общие доменные сервисы и PostgreSQL. Это проще поддерживать небольшой команде, чем набор микросервисов.

## Компоненты
```text
Browser / Telegram Mini App
          | HTTPS
      Reverse Proxy
          |
      FastAPI API -------- PostgreSQL
          |                     |
          +---- shared domain --+
          |
      Task queue / DB-backed jobs
          |
     Background Worker

Telegram Bot (aiogram) ---> shared application services
```

## Backend-модули
- `auth`: пользователи, сессии, восстановление доступа, Telegram linking.
- `accounts`: счета, участники и роли.
- `ledger`: операции, переводы, баланс и история.
- `categories`: категории и лимиты.
- `budgets`: бюджетные периоды и прогресс.
- `planning`: запланированные и повторяющиеся операции.
- `deposits`: вклады и расчёты.
- `analytics`: агрегаты и отчёты.
- `exports`: формирование XLSX.
- `notifications`: уведомления и расписание.
- `ai`: провайдеры и инструменты AI.
- `admin`: административные сценарии и аудит.

## Границы
HTTP handlers не содержат бизнес-логику. Они валидируют вход, вызывают application services и формируют ответ. Доступ к БД сосредоточен в repositories. Bot и worker не дублируют правила ledger — они вызывают те же сервисы, что и API.

## AI adapters
Провайдеры подключаются через единый интерфейс. Gemini — основной кандидат, OpenRouter — резервный. Секреты хранятся только на backend. При ошибке провайдера используется ограниченный retry/fallback; финансовые действия требуют явного подтверждения пользователя.

## Фоновые задачи
Worker обрабатывает повторения, напоминания, уведомления и генерацию тяжёлых отчётов. Задачи должны быть идемпотентными; повторный запуск не должен создавать дубли операций.

## Развёртывание
Локально: Docker Compose и отдельные процессы API, bot, worker, PostgreSQL. На VPS: reverse proxy с HTTPS, закрытая БД, резервное копирование и мониторинг. Production и development используют разные секреты и базы.

## Принятые ограничения
- Не вводить микросервисы до появления измеримой необходимости.
- Не запускать Telegram polling внутри API-процесса.
- Не использовать SQLite как production-хранилище.
- Не использовать float для денежных значений.
